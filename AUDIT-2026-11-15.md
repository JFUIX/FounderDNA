# FounderDNA site audit — 15 November 2026

Audited the nine HTML routes, shared assets, assessment, five guided brief variants, private dashboard/report, community, review desk, and connected Supabase database. The initial source baseline was `891dc34`; subsequent screenshot-only changes through `34ebc4f` were incorporated without modification.

## Findings and fixes

| Area | Finding | Resolution |
| --- | --- | --- |
| Loading | Homepage background PNG was 1,910,862 bytes; initial deployed mobile Lighthouse LCP was 12.2 s | Responsive WebP: 20,242 bytes mobile / 59,394 bytes desktop; matching media-specific preloads |
| Loading/privacy | CSS imports blocked rendering on external Google font requests | Locally hosted DM Sans, Manrope, Inter with variable weights, unicode subsets, swap rendering and font preloads; OFL licenses included |
| Loading | Anonymous marketing pages eagerly loaded the auth SDK | Lazy initialization on account use or existing session; dependent private tools still initialize immediately |
| Accessibility | Low contrast on About CTA and small community accent text | Correct foreground colors; automated WCAG checks pass |
| Accessibility | Unnamed dialogs and duplicate community aside landmarks | Explicit modal and landmark names |
| Accessibility | Dashboard/request headings skipped a level; request conversation labels had low contrast; assessment results lacked a focus target | Correct heading level and focusable result heading; wizard step transitions focus their heading |
| Dashboard | Progress report/download retained stale initial task and reflection data | Refresh on successful mutations, disable export while loading and ignore stale responses |
| Dashboard | Thrown network errors could strand disabled controls | Shared mutation error boundary restores controls and preserves unsaved input |
| Assessment | Repeated Save could insert identical results | Disable Save after successful insertion for that completed assessment |
| Briefs | Inactive portfolio URL could block unrelated requests; submit validation could focus hidden inputs | Validate only the active action/step and display the failing step before focusing |
| Drafts | A pending autosave could recreate a submitted brief draft | Cancel and clear pending timers after a confirmed receipt; preserve the autosave when cancelling Clear |
| Consent | Community publication checkbox stayed checked for the next draft | Clear publication consent after saving/resetting a milestone |
| Auth | Unavailable local storage prevented sign-in; stale sessions could leave private UI visible | Optional return-route storage; reload private UI when auth identity changes; load timeout with recovery message |
| Auth | Empty root filename made the return route invalid | Normalize root route to `index.html`; retain the existing exact `community.html` callback to preserve configured Supabase redirect allow-lists |
| Review desk | Failed status changes reverted to the original value instead of the latest successful value | Update the local request status after each confirmed change |
| Navigation/SEO | Assessment link appeared current on every page; canonical/social metadata and sitemap were missing | Actual current-page markers, canonical and public social metadata, public sitemap; private shells use noindex |
| Security | No browser content policy | Restrict scripts to self, the pinned Supabase SDK URL and hashes of existing inline code; limit connections, deny objects/base URLs and restrict form actions |
| Privacy notice | Saved assessments/dashboard records were not explained; font-provider statement was outdated | Describe optional account storage, deletion, 30-minute pending assessment copy, local reports and locally hosted fonts |
| Database | Two overlapping permissive milestone policies per authenticated SELECT/UPDATE action | Consolidated into equivalent per-role/action policies; live migration `consolidate_milestone_access_policies` applied; setup SQL updated |
| CI | Existing workflow omitted several routes/assets and tested only assessment spec | Pinned development dependencies and lockfile, reusable web-server config, full suite on PRs and relevant main changes |

## Verification evidence

- 45 browser tests across the original and expanded suite, with targeted reruns after findings were fixed. Includes all nine routes, internal page links, four viewport widths (320, 390, 768, 1440), public/authenticated accessibility scans, all five brief variants, downloads, draft clearing, duplicate-save prevention, report refresh, network failure recovery, and cross-tab sign-out.
- Authenticated browser integration uses a mocked Supabase client. It verifies UI behavior, not email delivery or a live browser session.
- Live database checks use temporary users and rows inside transactions that end with ROLLBACK. No test identities or data remain. Tests verify owner assessment/task/reflection operations, other-account read/update/delete denial, spoofed ownership denial, private milestone visibility, owner self-publication denial, reviewer approval, anonymous approved feed, approved replies, support RPC submission and request/conversation isolation.
- All 13 public application tables have RLS enabled. Existing private owner/date indexes are present. Authenticated-role EXPLAIN ANALYZE uses the appropriate indexes for assessment history, tasks and weekly reflections. Measurements with empty synthetic identities are not production-load benchmarks.
- Supabase performance advisor: overlapping-policy warnings resolved. Seven unused-index informational notices remain; indexes were retained because a new project's usage statistics do not establish that they are unnecessary.
- Final local mobile Lighthouse homepage: Performance 100, Accessibility 100, Best Practices 100, SEO 100; FCP 1.1 s, LCP 1.8 s, total blocking time 0 ms, CLS 0. This is a localhost laboratory run, not a production field measurement. The initial deployed result (Performance 64, LCP 12.2 s) used a different serving environment and is not a controlled before/after comparison.
- Browser checks in this managed environment ignore certificate-validation errors caused by its certificate chain. This does not validate public TLS configuration. CI uses normal browser certificate validation.

## Reproduce

```sh
npm ci
npx playwright install --with-deps chromium
npm test
```

The test config starts a local static server automatically. SQL tests in `tests/database-private-progress.sql` and `tests/database-community-service.sql` require a privileged database connection to create transactional fixtures and switch roles; run each entire script as a transaction. They deliberately ROLLBACK every fixture and must not be converted to migrations or deployed as application code.

Website changes are delivered through a PR. The database policy optimization is already applied to the connected project and works with both the existing and updated frontend.
